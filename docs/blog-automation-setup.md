# 자사 블로그 자동 발행 — 설정 가이드

챗지피티(ChatGPT Work) 예약 작업(Scheduled Tasks) + Skill로 2~3일마다 자동으로
블로그 초안을 쓰고, 대표님이 원터치로 승인하면 사이트에 게시되는 기능의 설정
방법입니다.

> **왜 Custom GPT Action이 아니라 Skill인가**: 처음엔 Custom GPT + Action으로
> 설계했지만, 2026년 기준 챗지피티 Scheduled Tasks는 **Custom GPT를 아예
> 지원하지 않습니다** ("Custom GPTs are not supported with tasks"). 예약
> 작업에서 쓸 수 있는 건 Skill이라, 이 문서는 Skill 기반으로 다시 작성했습니다.

## 이미 구축된 것

- `functions/api/blog/publish.ts` — 발행 API. 글을 받으면 대표 이미지를 R2에
  저장하고 **draft(초안) 상태로** Neon에 저장합니다. 이 시점엔 아직 공개 안 됨.
- `functions/api/blog/upload-image.ts` — 본문 중간에 들어갈 이미지(2~4장)를
  R2에 영구 저장하는 엔드포인트. 챗지피티가 생성한 이미지의 임시 URL은 며칠
  안에 만료되므로, 본문에 이미지를 넣으려면 반드시 이 API로 먼저 올려서 받은
  영구 URL을 마크다운에 써야 합니다.
- `functions/blog/review.ts` — 비공개 초안 검토 페이지. `/blog/review/?key=<BLOG_API_SECRET>`
  로 접속하면 draft 목록이 보이고, 글마다 "본문 보기"로 전체 내용을 확인할 수
  있습니다. 관리자 로그인 없이 URL의 key 파라미터로만 접근을 제어합니다.
- `functions/api/blog/approve.ts` — 검토 페이지의 "발행하기" 버튼이 호출하는
  엔드포인트. 누르는 즉시 해당 글이 published로 바뀌어 공개됩니다 (원터치 승인).
- `functions/blog/index.ts`, `functions/blog/[slug].ts` — 공개 블로그 목록/상세
  페이지. **Next.js 정적 페이지가 아니라 Cloudflare Pages Function**으로, 요청이
  올 때마다 Neon에서 published 글만 직접 읽어 그 자리에서 HTML을 렌더링합니다.
  승인하는 즉시 반영되고, 사이트 전체를 재배포할 필요가 없습니다. 글 끝에는
  항상 "무료 상담 신청하기" 버튼이 템플릿에서 고정으로 붙습니다.
- `functions/_lib/blog-html.ts` — 위 Function들이 공유하는 HTML 템플릿(헤더/푸터/
  스타일). 랜딩페이지의 `Header.tsx`/`Footer.tsx`와 별개의 순수 HTML이라, 그쪽
  네비게이션 메뉴가 바뀌면 이 파일도 같이 손봐야 합니다.
- `lib/db/schema.ts`의 `blog_posts` 테이블 (status: draft | published) — Neon에
  이미 생성 완료
- 시드 글 1편(`ecommerce-cashflow-first-post`, published 상태) — 챗지피티가 첫
  실제 글을 승인·발행하면 삭제 예정
- `public/robots.txt`, `functions/sitemap.xml.ts` — 네이버/구글 색인용 (아래
  "SEO 인프라" 참고)

만들어달라고 요청:

> 아래 조건으로 재사용 가능한 스킬을 하나 만들어줘. 이름은
> "moonjung-blog-publish" 정도로 해줘.
>
> **하는 일**: 문정세무회계컨설팅(이커머스 셀러 전문 세무회계 사무소) 블로그에
> 새 글의 초안을 자동으로 작성하고 등록한다. **이 블로그는 네이버와 구글
> 검색 노출이 목적이므로, 아래 SEO 기준을 반드시 지켜야 한다.**
>
> **대상 독자 / 주제 / 톤**:
> - 대상 독자: 쿠팡/네이버/자사몰/해외직구/틱톡샵 이커머스 셀러
> - 주제: 매번 다르게 — 현금흐름/흑자도산, 반품·부진재고 비용, 절세 노하우,
>   정책자금, 플랫폼별 세무 이슈 중 선택 (이전 글과 주제·구조·표현이 겹치지
>   않게 매번 구체적으로 다른 시나리오·숫자·사례를 사용할 것 — 네이버는
>   유사·중복 콘텐츠에 특히 민감함)
> - 톤: 친근하되 전문적으로, 정확한 세무 지식 기반. 실제 법령명·제도명을
>   정확히 인용하고, 추상적 조언 대신 구체적 수치·사례로 전문성을 드러낼 것
>   (이게 Google의 E-E-A-T와 네이버 C-Rank 둘 다에서 핵심 신호)
> - 금지: "업계 최고", "1위" 같은 근거 없는 최상급 표현 (한국 표시광고법 이슈),
>   AI가 쓴 티 나는 상투적 도입부("안녕하세요, 오늘은 ~에 대해 알아보겠습니다"
>   같은 문장) 금지
>
> **제목(title) 작성 기준**:
> - 실제 검색될 만한 핵심 키워드를 제목 앞부분에 그대로 배치 (예: "쿠팡 정산
>   세금 신고, 이 시점 놓치면 가산세" — "쿠팡 정산 세금"이 핵심 키워드).
>   너무 은유적이거나 창작적인 제목은 네이버 검색엔 불리하니 피할 것
> - 25~40자 내외 (너무 길면 검색결과에서 잘림)
> - 클릭베이트 대신 구체적 숫자·상황을 담아 실질적 궁금증을 자극할 것
>
> **메타 설명(excerpt) 작성 기준**: 이 필드가 검색결과 설명과 카드 미리보기에
> 그대로 쓰인다.
> - 80~120자, 핵심 키워드 1회 포함
> - 본문 요약이 아니라 "왜 지금 이 글을 읽어야 하는지"를 담을 것
>
> **본문(contentMarkdown) 작성 기준**:
> - 분량은 공백 제외 1500자 이상 (너무 짧으면 두 검색엔진 다 얕은 콘텐츠로 판단)
> - 첫 문단에 핵심 키워드를 자연스럽게 포함 (네이버·구글 둘 다 도입부 가중치가 큼)
> - **`#`(h1)은 절대 쓰지 말 것** — 페이지 제목이 이미 h1이라 본문에 또 쓰면
>   중복 h1으로 SEO 감점 요인이 된다. 소제목은 `##`(h2)부터 시작
> - 소제목(h2/h3)마다 핵심 키워드의 동의어·연관어를 자연스럽게 녹여 넣을 것
>   (예: "정산주기", "정산금", "플랫폼 정산" 등)
> - 문단은 3~5문장 단위로 짧게 끊고, 리스트·표로 정보를 구조화할 것 (모바일
>   가독성 + 스캔하기 쉬운 구조를 네이버가 특히 선호)
> - 키워드를 억지로 반복하지 말 것 (밀도 2~3% 내외가 자연스러움 — 과도한
>   반복은 두 검색엔진 다 스팸으로 감점)
> - 표절·재사용 금지: 기존에 이 스킬로 쓴 글이나 다른 사이트 내용을 그대로
>   옮기지 말 것. 네이버는 독창성 여부를 특히 엄격히 봄
> - 마무리 문단에 자연스럽게 상담 문의를 유도하는 문장 한 줄 포함 (사이트에
>   고정 CTA 버튼이 이미 붙지만, 본문에서도 자연스럽게 유도하면 도움됨)
>
> **이미지 사용 기준** (네이버 "부가세" 검색 상위 노출 글들을 분석해서 정한 기준):
> - **이미지 비율은 항상 3:2(가로형, 예: 1536×1024)로 생성할 것.** 세로형(3:4
>   등)이나 정사각형은 쓰지 말 것 — 사이트에서 대표 이미지는 원본 비율 그대로
>   보여주는데, 가로가 너무 좁거나 세로가 길면 모바일에서 글보다 이미지가
>   과도하게 길어져 보인다
> - 이미지 안의 제목·핵심 텍스트는 **가장자리에서 안쪽으로 8~10% 이상 여백을
>   두고** 배치할 것 (목록 페이지 카드에서는 비율이 안 맞으면 레터박스로
>   보여주지만, 텍스트가 가장자리에 바짝 붙어 있으면 시각적으로 답답해 보임)
> - 대표(썸네일) 이미지 1장 + **본문 이미지 10~15장**. 상위 노출 글들은
>   예외 없이 이미지 밀도가 매우 높다 — 짧은 단락(2~4문장)마다 이미지 하나
>   꼴로 넣을 것. 이미지가 적으면 안 된다
> - 각 이미지는 순수 장식이 아니라 그 구간의 핵심을 시각적으로 요약하는
>   **카드/배너 스타일**로 만들 것. 예:
>   - 섹션 제목을 큰 글씨로 강조한 배너 이미지
>   - 비교표를 카드 두 개로 시각화 (예: "무실적 신고 vs 일반 신고")
>   - 체크리스트/단계를 아이콘과 함께 나열한 카드
>   - 핵심 수치·기한을 강조한 경고/알림 스타일 카드
>   - 글 끝에 "핵심 3가지 정리" 같은 요약 카드
> - 이미지 색상·톤은 사이트 브랜드 컬러(남색 `#1B2A4A`, 오렌지 `#FF6B35`)에
>   맞춰 통일감 있게 만들 것
> - 한글이 깨끗하게 들어가야 함 (제목·핵심 문구 등)
> - 각 이미지는 관련 있는 단락 바로 근처에 배치하고, 마크다운
>   `![설명](영구URL)` 형식에 구체적인 설명(대체 텍스트) 포함
> - 이미지가 많아지더라도 세무 수치·설명을 이미지 안의 텍스트로만 전달하지
>   말 것 — 핵심 정보는 반드시 본문 텍스트나 표로도 함께 제공 (네이버·구글
>   둘 다 이미지 속 텍스트는 못 읽는다고 가정할 것). 이미지는 텍스트 내용을
>   시각적으로 "강조·요약"하는 역할이지 텍스트를 대체하는 역할이 아니다
> - **중요**: 본문에 넣는 이미지 하나하나마다(10~15장 전부 각각) 먼저
>   `POST https://moonjung.pages.dev/api/blog/upload-image`
>   (헤더 동일, 바디 `{"imageUrl": "<생성한 이미지의 임시 URL>"}`, 응답
>   `{"url": "<영구 URL>"}`)를 호출해서 받은 영구 URL을 써야 한다. 챗지피티가
>   준 임시 URL을 마크다운에 그대로 넣으면 며칠 안에 링크가 깨진다. 대표
>   이미지(`imageUrl` 필드)는 이 과정이 필요 없음 — publish 호출 시 자동으로
>   영구 저장된다.
>
> **링크 사용 기준**: 주장·수치 근처에 관련 정부기관·법령·플랫폼 공식 문서로
> 연결되는 출처 링크를 설명형 텍스트로(앵커 텍스트에 키워드 남발 금지) 자연스럽게
> 포함할 것. 관련 없는 링크나 순위 조작성 링크는 금지.
>
> **등록 방법**: 아래 API를 호출한다. 이 글은 바로 공개되지 않고 초안으로
> 등록되며, 사람이 검토 후 승인해야 실제로 게시된다.
> - `POST https://moonjung.pages.dev/api/blog/publish`
> - 헤더: `Authorization: Bearer <내가 알려줄 키>`, `Content-Type: application/json`
> - 바디(JSON): `title`(string), `excerpt`(string, 1~2문장 요약),
>   `contentMarkdown`(string, 마크다운 본문 — 본문 이미지는 위 upload-image로
>   받은 영구 URL만 사용), `imageUrl`(string, 대표 이미지의 임시 URL)
> - 성공 시 200과 `{success, slug, status:"draft"}` 응답, 실패 시 401/400/502와
>   `{error}` 응답
> - **안전장치**: upload-image 호출 없이 임시/추측 URL을 본문에 넣지 말 것.
>   이미지 업로드가 실패하면 URL을 임의로 만들어내지 말고 등록을 중단하고
>   실패로 보고할 것
>
> 실행할 때마다 결과(초안 등록 성공 여부, 어떤 제목으로 등록했는지, 실패했으면
> 이유)를 요약해서 알려줘.

### 4. 예약 작업(Scheduled Task) 설정
Skill이 만들어지면:
1. 챗지피티 사이드바 → **Scheduled** → 새 작업 만들기
2. 프롬프트에 `$moonjung-blog-publish`를 언급해서 이 스킬을 명시적으로 호출
3. 주기 설정 (이틀~사흘마다)
4. **예약 걸기 전에 일반 대화창에서 수동으로 한 번 먼저 실행**해서 정상 동작
   확인 (공식 권장 방식)

### 5. 초안 승인
새 초안이 등록되면 `https://moonjung.pages.dev/blog/review/?key=<BLOG_API_SECRET>`
에 접속 → 제목/요약/썸네일 확인 → "본문 보기"로 전체 내용 확인 → 문제없으면
**"발행하기"** 버튼 한 번 → 즉시 공개. 이 링크는 검토 대기 중인 글이 있을 때마다
직접 들어가서 확인하는 방식이라, 별도 알림(이메일 등)은 없습니다 — 필요해지면
나중에 추가 가능합니다.

## SEO 인프라 (구축 완료)

콘텐츠 작성 기준만으로는 검색 노출이 안 됩니다. 크롤링·색인에 필요한 기본
인프라가 없어서 같이 만들었습니다.

- `public/robots.txt` — 전체 크롤링 허용, `/blog/review/`(비공개 검토 페이지)만
  차단, sitemap 위치 명시
- `functions/sitemap.xml.ts` — `/sitemap.xml`. 정적 페이지 + Neon의 published
  블로그 글을 매 요청마다 실시간으로 합쳐서 생성 (빌드 시점에 못 아는 동적
  콘텐츠라 Function으로 구현)
- `functions/blog/[slug].ts`에 JSON-LD(`BlogPosting`) 구조화 데이터 추가 —
  구글 리치 결과용

### 대표님이 직접 하셔야 하는 것 (계정 소유자만 가능)

1. **네이버 서치어드바이저** (searchadvisor.naver.com) 사이트 등록 → 소유
   확인(HTML 태그 또는 파일 방식) → 사이트맵 제출: `https://moonjung.pages.dev/sitemap.xml`
2. **구글 서치 콘솔** (search.google.com/search-console) 속성 등록 → 소유
   확인 → 동일한 사이트맵 URL 제출
3. 등록 직후엔 색인까지 며칠~몇 주 걸릴 수 있습니다 (특히 네이버는 신규
   사이트 신뢰도가 쌓이는 데 시간이 필요). 글이 쌓이고 서치어드바이저/서치
   콘솔에서 "수집 요청"을 개별 URL마다 눌러주면 조금 더 빨라집니다.

## 확인 방법

1. Skill을 통해 초안 하나 등록
2. `/blog/review/?key=...`에서 뜨는지 확인
3. "발행하기" 눌러서 `/blog/`에 반영되는지 확인 (재배포 없이 즉시 반영)
4. `https://moonjung.pages.dev/sitemap.xml`에 정상적으로 뜨는지 확인
